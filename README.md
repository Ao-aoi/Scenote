# Scenote

LLM とユーザーが共同でゲームシナリオを構成・執筆するための、個人利用向けシナリオ制作アプリ。
仕様と開発方針は [CLAUDE.md](CLAUDE.md) を参照。

現在の実装範囲は Phase 1〜5（シナリオエディタ、AI チャットと提案レビュー、履歴・嗜好学習、iPad からの利用、可視化・構造管理）である。

- プロジェクト・章・場面・シナリオ要素（地の文・台詞・動作・演出・選択肢）の作成、編集、並べ替え、削除
- 場面単位の Markdown ソース編集（[記法](docs/markdown-format.md)、CodeMirror 6）
- 自動保存（SQLite）と、同時編集時の競合検出
- プロジェクト全体の Markdown / JSON 書き出し
- 参照ファイル（世界観・キャラクター設定など）の管理
- Gemini API を使った AI チャット（プロジェクトごとに複数）
- AI による変更提案の差分レビュー。**承認した提案だけ**がシナリオ・参照ファイルへ反映される
- 依頼に関係する参照ファイルの自動選択（チャット単位・依頼単位で指定や除外も可能）
- API 使用量の集計と、上限到達時の自動停止

- AI の提案を修正してから採用する操作
- 編集履歴（人間の編集・AI 提案の承認・修正して採用・復元を区別して記録）
- 手動スナップショット（メモつき）の作成・現在との比較・復元。復元前の状態は自動で保存される
- 執筆嗜好の学習: 提案への操作を分析し、根拠と確信度つきのルールとして管理する。初期設定では更新案を承認したものだけを反映する

- 同じ LAN の iPad などからの利用（ペアリングによる端末の登録、変更のリアルタイム同期、同時編集の競合検出）

- 変数（数値・真偽値・文字列）と、選択肢・遷移の条件式（例: `好感度 >= 3 and 鍵`）・変更式（例: `好感度 += 1`）
- 場面・分岐グラフとキャラクター相関図の表示、構造チェック（移動先の欠落、式の誤り、到達できない場面など）
- キャラクター（情報・関係）を独立したデータとして保存する基盤
- AI でキャラクター・世界観・ストーリー（章・場面の概要）を段階的に作る「作品づくり（AI）」。案は採用したものだけが登録される
- 場面の概要（プロット）と、AI によるプロットの提案
- かんたんモード: スマートフォンでは自動で、iPad・PC ではメニューから切り替えて、会話・プロット・本文に絞った画面で使える
- 執筆嗜好の分析の自動実行（設定で有効にした場合）

## 構成

| ディレクトリ | 内容 |
|---|---|
| `server/` | Rust（axum + SQLite）のローカルサーバー。データ管理・Markdown 変換・HTTP API |
| `web/` | TypeScript + Vite の Web UI |
| `docs/` | 仕様書（Markdown 記法など） |

## 必要なもの

- Rust（stable）
- Node.js 20 以降

## 起動方法

リポジトリのルートで実行する。

```bash
cd web
npm install
npm run build
cd ..
cargo run --release --manifest-path server/Cargo.toml
```

ブラウザで <http://127.0.0.1:8787> を開く。データは `data/scenote.db` に保存される。

| 環境変数 | 既定値 | 説明 |
|---|---|---|
| `SCENOTE_ADDR` | `127.0.0.1:8787` | 待ち受けアドレス |
| `SCENOTE_DB` | `data/scenote.db` | SQLite データベースのパス |
| `SCENOTE_WEB_DIR` | `web/dist` | ビルド済み Web UI のディレクトリ |
| `GEMINI_API_KEY` | （なし） | Gemini API キー。画面の「AI 設定」からも登録できる |
| `SCENOTE_LAN` | （なし） | `1` にすると同じ LAN の端末にも公開する（`0.0.0.0:8787` で待ち受け） |

## iPad から使う

1. PC でサーバーを LAN 公開つきで起動する。PowerShell の場合:

   ```powershell
   $env:SCENOTE_LAN = "1"; cargo run --release --manifest-path server/Cargo.toml
   ```

   起動時に接続先 URL と QR コードが PowerShell に表示される。iPad のカメラで QR コードを読み取ると Safari で開ける。初回は Windows のファイアウォールの確認が出るので、**プライベート ネットワーク**での通信を許可する。
2. PC のブラウザで <http://localhost:8787> を開き、「設定」→「端末の接続…」→「ペアリングコードを発行」を押す。
3. iPad の Safari で表示されたアドレスを開き、8 桁のコードと端末名を入力する（コードは 10 分間・一度だけ有効）。
4. 以後、iPad と PC の変更は互いの画面に自動で反映される。同じ箇所を同時に編集した場合は、上書きせずにどちらの内容を残すか選ぶ画面が出る。

- 接続した端末は「端末の接続…」から一覧・解除できる。
- API キーの登録・変更と端末の管理は、安全のため PC 本体の画面からのみ行える。
- 通信は暗号化されていない HTTP である。自宅など信頼できるネットワークでのみ使うこと。

## AI を使う

1. [Google AI Studio](https://aistudio.google.com/) で Gemini API キーを発行する。
2. 画面右上の「AI」でチャットを開き、「⋯」→「AI 設定・使用量…」で API キーを登録する。キーはこの PC のデータベースにのみ保存され、画面へは返されない。
3. 場面を開いた状態で依頼を送る。AI の変更は提案として表示されるので、差分を確認して承認または却下する。

既定のモデルは `gemini-flash-latest`（最新の Flash を指す別名）。利用できるモデル名・料金・無料枠は変更されるため、公式ページで確認のうえ「AI 設定」で変更する。
月あたりのトークン上限（初期値 200 万）に達すると AI の利用は自動停止し、上限を変更するか明示的に再開するまで止まったままになる。

## 開発

```bash
# サーバーのテスト
cargo test --manifest-path server/Cargo.toml

# Web UI の開発サーバー（API は 127.0.0.1:8787 へ中継される。別ターミナルでサーバーを起動しておく）
cd web
npm run dev
```
